# Task 4 evaluation review

## Ranked findings

1. **[P1] Preserve the fixed station denominator in point bootstrap replicates.** `src/gnss_field/evaluation/bootstrap.py`, lines 48–53, accepts a resample whenever any population element remains. `point_metrics` then excludes stations with zero sampled observations. Protocol section 8 requires redraws and a recorded rejection rate when a station has no observations, so every accepted replicate retains the declared station-macro population. A four-day, two-station probe with disjoint two-day availability blocks and constant station errors of 1 and 10 mm gives an observed macro difference of 5.5 mm. Accepted bootstrap replicates return 1, 5.5 and 10 mm as the station count changes between one and two. Preserve the originally scored station IDs, reject incomplete draws and record rejected draws. Handle wholly empty draws through the same mechanism with a bounded exhaustion outcome.

2. **[P1] Build crossed-bootstrap group draws from groups observed in the fixed endpoint population.** `src/gnss_field/evaluation/bootstrap.py`, lines 76–97, constructs its group list from every pair column before applying the endpoint population. The documented caller masks the pair population to the registered distance range and common T. Some groups can therefore have zero valid pairs throughout the scored period. These groups enter group draws and inflate `n_groups`, while the observed statistic excludes them. A two-column probe with groups `a,b` and population columns `True,False` raises `ValueError('A crossed resample has no declared pair observations')` during 20 replicates with the default seed. Select the observed endpoint groups once, retain their fixed IDs and counts, and handle time draws that remove required selected groups through explicit rejection and reporting. The current `continue` also silently drops selected groups in partially observed draws and changes their intended macro weights.

3. **[P2] Apply startup eligibility consistently when choosing Bstar.** `src/gnss_field/evaluation/selection.py`, lines 64–67, excludes step 200 but accepts learned-model steps 0–199. The learned-product selector excludes every step through 200. A registered M0 record at refinement step 100 with RMSE 0.1 mm is selected over its eligible step-1000 record at 1 mm. Distinguish registered fixed nontrained controls from learned checkpoints, preserve legal step-zero fixed controls and require learned Bstar candidates to pass the same startup exclusion.

4. **[P2] Store the normalized checkpoint digest returned by `_hash`.** `src/gnss_field/evaluation/selection.py`, lines 123–126 and 152–154, validates a selected checkpoint digest through `_hash` and stores its original spelling. `_hash` accepts uppercase hexadecimal and returns lowercase. Retrospective validation normalizes its argument, then compares it to the original stored spelling. A lock built successfully with a checkpoint digest of 64 uppercase `B` characters rejects that same checkpoint during access validation. Normalize the stored digest before computing the lock fingerprint.
